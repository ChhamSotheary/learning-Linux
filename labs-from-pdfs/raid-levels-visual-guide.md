# RAID Levels៖ មគ្គុទ្ទេសក៍ជារូបភាព

មេរៀននេះប្រៀបធៀប RAID 0, 1, 5, 6 និង 10 ដោយប្រើរូបភាពសាមញ្ញ។ សញ្ញា **A1, A2** ជាបំណែកទិន្នន័យ; **P, Q** ជា parity ដែលប្រើសម្រាប់គណនាទិន្នន័យដែលបាត់។ រូបភាពបង្ហាញគោលគំនិត មិនមែនជាទម្រង់ពិតនៃ block layout ក្នុងគ្រប់ controller ទេ។

## មុនប្រៀបធៀប៖ ស្គាល់ពាក្យសំខាន់

- **Striping**៖ បំបែកទិន្នន័យជាបំណែក ហើយចែកសរសេរលើ disks ច្រើន។ អាចបង្កើនល្បឿន ប៉ុន្តែ striping តែមួយមុខមិនមានច្បាប់ចម្លងការពារ disk ខូចទេ។
- **Mirroring**៖ រក្សាទុកច្បាប់ចម្លងទិន្នន័យដូចគ្នាលើ disks ច្រើន។
- **Parity**៖ ព័ត៌មានបន្ថែមដែលប្រើគណនាឡើងវិញនូវទិន្នន័យពេល disk ខូច។ វាមិនមែនជាច្បាប់ចម្លងពេញលេញដូច mirror ទេ។
- **Usable capacity**៖ ទំហំដែលអាចរក្សាទុកទិន្នន័យបាន បន្ទាប់ពីទំហំសម្រាប់ mirror ឬ parity ត្រូវបានប្រើ។
- ក្នុងរូបភាពខាងក្រោម សន្មតថា disks មានទំហំស្មើគ្នា។ បើទំហំមិនស្មើ គេជាទូទៅគិតតាម disk តូចបំផុត។

## RAID 0៖ Striping

~~~text
                 Disk 1       Disk 2
ទិន្នន័យ A  →     [ A1 ]       [ A2 ]
ទិន្នន័យ B  →     [ B1 ]       [ B2 ]
ទិន្នន័យ C  →     [ C1 ]       [ C2 ]
~~~

ទិន្នន័យត្រូវបានបំបែកចែកលើ disks។ RAID 0 មិនមាន mirror ឬ parity ទេ។

- **ចំនួន disks អប្បបរមា**៖ 2
- **ទំហំប្រើបាន**៖ ចំនួន disks × ទំហំ disk តូចបំផុត
- **បើ disk មួយខូច**៖ array ទាំងមូលអាចបាត់ទិន្នន័យ
- **សមស្របសម្រាប់**៖ ទិន្នន័យបណ្តោះអាសន្នដែលអាចបង្កើតឡើងវិញបាន និងត្រូវការល្បឿន
- **មិនសមស្របសម្រាប់**៖ ទិន្នន័យតែមួយច្បាប់ ឬសេវាដែលត្រូវការភាពធន់

## RAID 1៖ Mirroring

~~~text
                 Disk 1       Disk 2
ទិន្នន័យ A  →     [  A  ]  =   [  A  ]
ទិន្នន័យ B  →     [  B  ]  =   [  B  ]
ទិន្នន័យ C  →     [  C  ]  =   [  C  ]
                       ច្បាប់ចម្លងដូចគ្នា
~~~

Disk មួយមានទិន្នន័យដូច disk មួយទៀត។ ពេល disk មួយខូច mirror អាចបន្តផ្តល់ទិន្នន័យពីសមាជិកដែលនៅល្អ—បើ configuration និងសមាជិកដែលនៅសល់ដំណើរការ។

- **ចំនួន disks អប្បបរមា**៖ 2
- **ទំហំប្រើបាន**៖ សម្រាប់ mirror ពីរ ប្រហែលទំហំ disk មួយ
- **បើ disk មួយខូច**៖ អាចបន្តបាន; ត្រូវជំនួសសមាជិកខូច ហើយ rebuild
- **ចំណុចពិសេស**៖ ការលុបឯកសារខុសក៏ត្រូវបាន mirror ដែរ; ត្រូវមាន backup

**ឧទាហរណ៍**៖ disk 10 GB ពីរ → ប្រហែល 10 GB usable មិនមែន 20 GB។

## RAID 5៖ Striping ជាមួយ parity មួយ

ឧទាហរណ៍មាន disks បី។ P តំណាងឱ្យ parity block ហើយទីតាំង parity ផ្លាស់ប្តូររវាង disks ក្នុង array ពិតជាច្រើន។

~~~text
                 Disk 1       Disk 2       Disk 3
stripe 1          [ A1 ]       [ A2 ]       [ P1 ]
stripe 2          [ B1 ]       [ P2 ]       [ B2 ]
stripe 3          [ P3 ]       [ C1 ]       [ C2 ]
~~~

RAID 5 ចែក data និង parity លើ disks ទាំងអស់។ Parity អាចជួយស្ដារទិន្នន័យពេល disk មួយខូច។

- **ចំនួន disks អប្បបរមា**៖ 3
- **ទំហំប្រើបាន**៖ (ចំនួន disks − 1) × ទំហំ disk តូចបំផុត
- **បើ disk ខូច**៖ អាចទ្រាំបានមួយ; array នឹង degraded រហូតដល់ rebuild
- **ចំណុចប្រុងប្រយ័ត្ន**៖ rebuild អាចចំណាយពេល; disk មួយទៀតខូចក្នុងអំឡុងពេលស្ដារអាចធ្វើឱ្យទិន្នន័យបាត់

**ឧទាហរណ៍**៖ disk 10 GB បី → ប្រហែល 20 GB usable។

## RAID 6៖ Striping ជាមួយ parity ពីរ

Q ជា parity បន្ថែមមួយទៀត។ រូបភាពនេះបង្ហាញគំនិតប៉ុណ្ណោះ; ការចែក block ជាក់ស្តែងអាស្រ័យលើ implementation។

~~~text
                 Disk 1       Disk 2       Disk 3       Disk 4
stripe 1          [ A1 ]       [ A2 ]       [ P1 ]       [ Q1 ]
stripe 2          [ B1 ]       [ P2 ]       [ Q2 ]       [ B2 ]
stripe 3          [ P3 ]       [ Q3 ]       [ C1 ]       [ C2 ]
~~~

- **ចំនួន disks អប្បបរមា**៖ 4
- **ទំហំប្រើបាន**៖ (ចំនួន disks − 2) × ទំហំ disk តូចបំផុត
- **បើ disk ខូច**៖ អាចទ្រាំបានពីរ ក្នុងកម្រិតដែល layout និង implementation គាំទ្រ
- **ចំណុចពិសេស**៖ ចំណាយទំហំច្រើនលើ parity ជាង RAID 5 ប៉ុន្តែមានភាពធន់បន្ថែម

**ឧទាហរណ៍**៖ disk 10 GB បួន → ប្រហែល 20 GB usable។

## RAID 10៖ Mirror pairs បូក striping

RAID 10 (ជាញឹកញាប់សរសេរ RAID 1+0) បង្កើត mirror pairs ជាមុន រួច stripe ទិន្នន័យលើ pairs។ ខាងក្រោមសន្មតថា mirror pair មាន Disk 1+2 និង Disk 3+4។

~~~text
Mirror pair A:  Disk 1 [ A ][ B ][ C ]  ⇄  Disk 2 [ A ][ B ][ C ]
Mirror pair B:  Disk 3 [ D ][ E ][ F ]  ⇄  Disk 4 [ D ][ E ][ F ]

             striping ចែកទិន្នន័យលើ mirror pairs
~~~

- **ចំនួន disks អប្បបរមា**៖ ជាទូទៅ 4
- **ទំហំប្រើបាន**៖ ប្រហែលពាក់កណ្ដាលទំហំសរុប
- **បើ disk ខូច**៖ អាស្រ័យលើ mirror pair ដែលខូច; អាចទ្រាំ disk ច្រើនជាងមួយ ប្រសិនបើមិនខូចទាំងពីរក្នុង pair ដូចគ្នា
- **ចំណុចពិសេស**៖ ជាទូទៅផ្តល់ performance និងការស្ដារល្អ ប៉ុន្តែប្រើទំហំសម្រាប់ mirror ប្រហែលពាក់កណ្ដាល

**ឧទាហរណ៍**៖ disk 10 GB បួន → ប្រហែល 20 GB usable។ បើ Disk 1 និង Disk 2 ខូចទាំងពីរ នោះ Mirror pair A បាត់ ហើយ array អាចបរាជ័យ។

## តារាងប្រៀបធៀបរហ័ស

| RAID | Disks អប្បបរមា | របៀបការពារ | ទំហំប្រើបានប្រហែល | Disk ខូចដែលអាចទ្រាំបាន |
|---|---:|---|---|---|
| 0 | 2 | គ្មាន mirror/parity | N × ទំហំ disk តូចបំផុត | 0 |
| 1 | 2 | ចម្លងទិន្នន័យ | 1 × ទំហំ disk សម្រាប់ mirror ពីរ | 1 ក្នុង mirror ពីរ |
| 5 | 3 | parity មួយ | (N−1) × ទំហំ disk តូចបំផុត | 1 |
| 6 | 4 | parity ពីរ | (N−2) × ទំហំ disk តូចបំផុត | 2 |
| 10 | 4 ជាទូទៅ | mirror pairs + striping | ប្រហែល N/2 × ទំហំ disk | អាស្រ័យលើ pair |

N មានន័យថាចំនួន disks។ ចំនួន disk failure ដែល RAID 1 ឬ RAID 10 អាចទ្រាំបាន អាស្រ័យលើ layout និងថាតើ disk ខូចនៅ mirror pair ណា។ សម្រាប់ RAID 5/6 ចំនួនដែលបានរាយត្រូវអនុវត្តតាម implementation និងស្ថានភាព array។

## ជ្រើស RAID តាមគោលបំណង

- ជ្រើស **RAID 0** នៅពេលល្បឿនសំខាន់ និងទិន្នន័យអាចបង្កើតឡើងវិញបាន។
- ជ្រើស **RAID 1** សម្រាប់ mirror សាមញ្ញដែលមាន disks ពីរ និងទទួលយក usable capacity ប្រហែលពាក់កណ្ដាល។
- ពិចារណា **RAID 5** នៅពេលចង់បាន usable capacity ច្រើនជាង mirror និងអាចទ្រាំ disk ខូចមួយ។
- ពិចារណា **RAID 6** នៅពេលចង់បាន parity ពីរ និងមាន disks យ៉ាងតិចបួន។
- ពិចារណា **RAID 10** នៅពេលចង់បាន mirror និង striping ហើយទទួលយក usable capacity ប្រហែលពាក់កណ្ដាល។

ការជ្រើសសម្រាប់ប្រព័ន្ធពិតត្រូវពិនិត្យ controller/software, workload, rebuild time, monitoring, spare disks និងផែនការ backup។ RAID levels និងសមត្ថភាពខុសគ្នាតាម implementation។

## សំខាន់៖ RAID មិនមែន Backup

RAID ជួយរក្សា service ឱ្យដំណើរការពេល disk ខូចតាមកម្រិតដែល RAID នោះគាំទ្រ។ វាមិនការពារប្រឆាំងនឹងការលុបខុស, ransomware, corruption, ការខូចម៉ាស៊ីន ឬគ្រោះថ្នាក់ដែលប៉ះពាល់ដល់ disks ទាំងអស់ទេ។ ត្រូវមាន backup ដាច់ដោយឡែក ហើយសាកល្បង restore ឱ្យដឹងថាអាចស្ដារបាន។
